Cover nodes

Cover controller

Message shapes, output ports and settings for one blind, shutter or curtain. Position-aware confirmation without fighting manual moves.

On this pageOne motor. One command owner.InputsOutputsSettingsOptional MQTT and Home AssistantOpen, close and stop only
home-cover-controller1 input · 4 outputshome automation

One motor. One command owner.

Controls a blind, shutter or curtain in position mode or open-close mode. It confirms moves from cover reports, retries within its limits, and leaves a person’s move where they put it.

Looking for wiring?

Follow Wire a cover for the MQTT adapter connections and a working message path.

Inputs

Requests and device observations share the same input. A position cover uses 0 for closed and 100 for open.

Input properties
PropertyTypeMeaning
msg.payloadstring / number"open", "close", "stop", a position from 0 to 100, or a preset name. An already satisfied, still target needs no command.
msg.stopIfMovingbooleanWith true, stop if moving (including an unconfirmed move); otherwise carry out the request.
msg.respectManualbooleanWith true, wait while a person’s move holds the cover. A request without this takes control back.
msg.coverobjectObservation, availability, startup, command result, or a full cover request. See message shapes below.
msg.status from a Status nodeMQTT out’s “connected”Taken as the startup message (msg.cover = {kind: "startup"}), so the node announces itself again once the broker can take it. Wire in a Status node whose scope is your MQTT out node. Any other status message is ignored.
Device observation · msg.cover
{
  kind: "observed",
  position: 60,
  motion: "stopped",
  observedAt: "2026-01-01T12:00:00.000Z"
}

Motion is opening, closing or stopped. Optional battery and charging fields are kept as reported facts, not acted on.

Outputs

The port order is fixed. Device commands and optional MQTT publications have different jobs.

Four output ports
PortMessageConnect to
1 · Device commandsmsg.cover_command = {operation, position, requestId, generation, attempt}
Position mode: set_position, stop, observe.		Device adapter. For example, the shelly cover node’s input.
2 · State and resultsmsg.theatre = {kind: "target_state", target: "cover", status, details}Debug, a cover group, or another result consumer. Contains positions and failure or manual-override details.
3 · Movingmsg.payload true / false; msg.topic = "moving". Sent on changes.Policies that need to react to cover motion.
4 · MQTT publicationsRetained state and optional discovery, when publishing is on.MQTT out; not the device-command path.
Completion needs a stopped target.

A stopped motion report confirms the target, or it must remain at the same position for the settle time. A command echo alone does not prove that travel is finished.

Optional MQTT and Home Assistant

Publishing and discovery are off by default. When publishing is on, set both Area and Name in topics. The base topic is home/<area>/cover/<name>.

Published state and incoming requests
Topic suffixDirectionPayload
/stateOutput 4 · retainedopen, closed, opening, closing or stopped, once reported.
/positionOutput 4 · retainedReported position, for a position cover.
/availabilityOutput 4 · retainedonline or offline.
/setMQTT in → controllerOPEN, CLOSE or STOP.
/position/setMQTT in → controllerRequested position.

Subscribe to home/<area>/cover/<name>/set and, for a position cover, …/position/set, and feed the MQTT in messages to the controller. Anything else on the cover’s own topics, and any other cover’s topics (home/<area>/cover/<name>/…), such as their state, position and availability coming back through a wildcard subscription, is ignored, with a trace, whether or not this cover publishes. A cover group’s requests, named by their member, and a flow’s own topics are requests as before. These are requests to the controller, never direct commands through Home Assistant. Do not retain command or request messages.

Open, close and stop only

For a motor without a reliable position, set Cover to “Open, close and stop only”. Positions and presets are ignored. Commands on output 1 become open, close, stop or observe.

Report msg.cover = {kind: "observed", motion, state, observedAt}. A reported end state (open or closed) confirms the move. Otherwise, a move in the requested direction that stops after the full travel time is explicitly judged by travel time.

Stopping early or moving the other way is treated as a person’s move. If the motor reports nothing, the result stays unconfirmed and fails with no-reports after the retry limit.
