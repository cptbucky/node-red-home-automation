House schedule MQTT

Message shapes, output and settings for the node that publishes a house schedule’s times over MQTT and takes changes back. Optional: rooms follow the schedule without it.

On this pageThe schedule’s MQTT side.InputsOutputsSettingsMQTT and Home AssistantStatus
home-house-schedule-mqtt1 input · 1 outputhome automation

The schedule’s MQTT side.

Publishes a house schedule’s wake and bed times as retained MQTT state and, with discovery, as Home Assistant time entities, and changes the schedule from their set topics or from a message. In the palette it is home-house-schedule-mqtt; on the canvas it shows its name, or “house schedule MQTT”.

Use one per schedule: two would share the same topics and entities, and deleting one clears them for both until the other next starts.

Looking for wiring?

Follow Share a house schedule for the full flow, and Use Home Assistant as the panel for the entities.

Inputs

Wire an MQTT in node subscribed to the set topics into the input.

Input messages
MessageShapeEffect
Time from Home Assistantmsg.topic = home/<name>/schedule/wake-time/set or …/bed-time/set, msg.payload a timeSets that time. Retained messages and anything but a time are ignored.
New timesmsg.lighting = {kind: "schedule", wakeTime, bedTime}, each HH:MM, either one aloneSets the schedule’s times.
Startupmsg.source = "startup" (or msg.lighting.kind = "startup")Announce again, as after the broker reconnects.
msg.status from a Status nodeMQTT out’s “connected”Taken as the startup message (msg.source = "startup"), so the node announces itself again once the broker can take it. Wire in a Status node whose scope is your MQTT out node. Any other status message is ignored.

A time changed this way lasts until a deploy gives the house schedule a different Wake time or Bed time. Every policy following the schedule hears of the change without wires.

Outputs

One output port
PortMessageConnect to
1 · MQTT publicationsRetained times, availability and discovery messages. Sent at start, at every change to the schedule, and when it stops.An MQTT out node.

Settings

Defaults below are from the editor definition.

Editor settings and exact defaults
Setting / propertyDefaultMeaning
Namename · stringEmptyDisplay label; a new palette node starts unnamed.
Scheduleschedule · home-house-scheduleNoneRequired. The house schedule to publish; its name names the topics. Without one, or with a deleted one, the node shows invalid configuration and does nothing.
PublishhomeAssistant · enumMQTT state and Home Assistant discovery, for a new nodeMQTT state (state): the schedule’s wake and bed times and its availability, with its set topics, plain MQTT for any system to read; MQTT state and Home Assistant discovery (discovery): that, and wake and bed time entities announced to Home Assistant, which read that state. It always publishes its state, so there is no Don’t publish. It replaced Home Assistant discovery (discovery): a node saved before reads off as MQTT state and on as MQTT state and Home Assistant discovery; a flow saved without either gets MQTT state.
Brokerbroker · mqtt-brokerNoneNode-RED’s MQTT broker node, through which it publishes and reads its set topics itself: it runs its startup each time the broker connects, reconnects included (its announcement, and whatever else its startup does, as a Status node’s “connected” did), announces everything again each time Home Assistant comes back, and output 1 and an MQTT in on its set topics are then no longer needed. It always publishes, so it needs one; opening and saving the node offers the first broker in your flows. A node saved before 6.2 that publishes keeps publishing through output 1, as before, and needs no broker until you choose one: the editor says so, and keeps that when you save it without a broker (publishesThroughOutput, with no form row). Without a broker, it publishes on output 1.
Discovery prefixdiscoveryPrefix · stringhomeassistantHome Assistant discovery topic prefix. Must not be empty or contain + or #.

New nodes use node-based Home Assistant identifiers (idScheme = "node"). That internal marker is set when a node is added from the palette; it is not an editor setting. This node has no older entities, so an unset idScheme also means node-based. Entities are named after the schedule, not this node, so a replacement node keeps them.

MQTT and Home Assistant

Publishing is what this node is for, so its state is always published. The base topic is home/<name>/schedule, from the house schedule’s Name.

Published state and incoming requests
Topic suffixDirectionPayload
/wake-time/stateOutput 1 · retainedThe wake time as HH:MM:SS.
/bed-time/stateOutput 1 · retainedThe bed time as HH:MM:SS.
/availabilityOutput 1 · retainedonline or offline.
/wake-time/setMQTT in → nodeA new wake time. Not retained.
/bed-time/setMQTT in → nodeA new bed time. Not retained.

With discovery on, Home Assistant gets two time entities, Wake time and Bed time, reading the state topics and commanding the set topics. They change the schedule, never a device.

Status

The node status shows the times in use, wake HH:MM · bed HH:MM (green), and updates at every change.
