Lighting nodes

Occupancy fusion

Message shapes, output ports and settings for the node that turns PIR motion, and optionally presence, into one occupancy signal. Motion establishes occupancy; presence can only hold it.

On this pageMotion establishes. Presence holds.InputsOutputsSettingsOptional MQTT and Home AssistantStatus
home-occupancy-fusion1 input · 2 outputshome automation

Motion establishes. Presence holds.

Combines normalised motion and optional presence events into one occupancy event, msg.source = "occupancy", for the motion lighting policy. In the palette it is home-occupancy-fusion; on the canvas it shows its name, or “<area> occupancy”, or “occupancy”.

A PIR sensor establishes occupancy. A presence sensor (such as mmWave) can keep an established occupancy going while motion is clear, but it cannot establish occupancy by itself.

Looking for wiring?

Follow Light a room from motion for the sensor connections and the motion lighting policy after it.

Inputs

Each message names its sensor in msg.source. Other sources are ignored.

Input messages
msg.sourcemsg.payloadEffect
"motion"A boolean, a string, or an object with motion, occupancy or activeMotion on makes the area occupied. Motion off makes it vacant unless a held presence keeps it.
"presence"A boolean, a string, or an object with presence, occupancy or activeOnly with Presence sensor set to hold. Presence on holds occupancy that motion established; presence off with motion off makes the area vacant.
"startup"AnyAnnounce the MQTT publications again, as after the broker reconnects.
msg.status from a Status nodeMQTT out’s “connected”Taken as the startup message (msg.source = "startup"), so the node announces itself again once the broker can take it. Wire in a Status node whose scope is your MQTT out node. Any other status message is ignored.

Strings read as on: on, true, occupied, active, detected. Strings read as off: off, false, clear, inactive, not_detected. Case does not matter; anything else is ignored.

A baseline. A motion or presence message with msg.baseline = true is the sensor’s state as Node-RED starts, such as an ESPHome sensor’s retained state while the device is online (Everything Presence One, Apollo R PRO-1): the room as it is, not a new detection. On (motion or presence) makes the area occupied and sends nothing, so no light is switched on; motion acts from its next change. Off is read as usual, so an empty room sends occupied: false and the motion policy starts its vacancy countdown.

Motion from a sensor · msg
{
  source: "motion",
  payload: {motion: true}
}

Outputs

The port order is fixed.

Two output ports
PortMessageConnect to
1 · Occupancy eventsmsg.source = "occupancy", msg.payload = {kind: "occupancy", occupied, trigger, reason, sources}. Sent on motion and presence edges, as below.The motion lighting policy’s input.
2 · MQTT publicationsRetained state, availability and discovery messages, when publishing is on.An MQTT out node.
  • occupied: true on every motion edge from off (or unknown) to on, even when a held presence already kept the area occupied.
  • occupied: false when motion goes off with no presence holding, or presence goes off with motion off, if that sensor was on or not yet known, or the area was occupied. So the first off report from a sensor not yet known (such as after its context is lost) is sent even when the area is already vacant.
  • Presence on never sends an event: it only holds occupancy that motion established.

trigger is "motion" when motion made the area occupied, otherwise null. reason is motion-active or all-sources-inactive. sources gives the last known motion and presence, each true, false or null when unknown or not used.

Settings

Defaults below are from the editor definition.

Editor settings and exact defaults
Setting / propertyDefaultMeaning
Namename · stringEmptyDisplay label; a new palette node starts unnamed.
Areaarea · stringEmptyRequired when publishing, and then with a letter or digit. Topics use it in lowercase, with spaces and other characters as _.
Presence sensorpresenceMode · enumnonenone: PIR only, presence messages are ignored. hold: PIR plus a presence sensor that holds occupancy.
PublishhomeAssistant · enumDon’t publishDon’t publish (off); MQTT state (state): its occupancy and availability, plain MQTT for any system to read; MQTT state and Home Assistant discovery (discovery): that, and an occupancy binary sensor announced to Home Assistant, which read that state. It replaced Publish state over MQTT (publishState) and Home Assistant discovery (discovery): a node saved before reads off/off as Don’t publish, on/off as MQTT state and on/on as MQTT state and Home Assistant discovery.
Brokerbroker · mqtt-brokerNoneNode-RED’s MQTT broker node, through which it publishes itself: it runs its startup each time the broker connects, reconnects included (its announcement, and whatever else its startup does, as a Status node’s “connected” did), announces everything again each time Home Assistant comes back, and output 2 are then no longer needed. Needed unless Publish is Don’t publish; opening and saving the node offers the first broker in your flows. A node saved before 6.2 that publishes keeps publishing through output 2, as before, and needs no broker until you choose one: the editor says so, and keeps that when you save it without a broker (publishesThroughOutput, with no form row). Without a broker, it publishes on output 2.
Discovery prefixdiscoveryPrefix · stringhomeassistantHome Assistant discovery topic prefix. Must not be empty or contain + or #.

New nodes use node-based Home Assistant identifiers (idScheme = "node"). That internal marker is set when a node is added from the palette; it is not an editor setting. Occupancy has no older entities, so an unset idScheme also means node-based.

Optional MQTT and Home Assistant

Publishing and discovery are off by default. When publishing is on, set Area. The messages go on output 2.

Published topics
TopicDirectionPayload
home/<area>/occupancy/stateOutput 2 · retainedON or OFF, with every occupancy event on output 1.
home/<area>/occupancy/availabilityOutput 2 · retainedonline or offline.

With discovery on, Home Assistant gets an occupancy binary sensor reading that state. The node announces itself once the flows have started, and again when it receives msg.source = "startup". It is a view only: occupancy never goes to devices through Home Assistant. See Use Home Assistant as the panel.

Status

The node status shows occupied (green) or vacant (grey), followed by pir on or pir off once motion is known, and presence on or presence off once presence is known and in use.
