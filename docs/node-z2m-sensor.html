A sensor’s reports, as the room takes them

The zigbee2mqtt sensor node (type home-z2m-sensor; canvas label: its name, its friendly name, or “zigbee2mqtt sensor”) turns a Zigbee2MQTT sensor’s state reports into the messages occupancy fusion and the motion lighting policy take. It subscribes through Node-RED’s MQTT broker node itself: no MQTT in, change or function nodes, and never Home Assistant.

Looking for wiring?

Follow Motion and occupancy.

The devices: Zigbee2MQTT’s supported devices (its page there names each device’s fields).

Inputs

The broker<base>/<friendly name>: the device’s state as JSONIts occupancy, presence and light level, as below.

An MQTT in node wired to its input changes nothing.

Outputs

Two output ports
PortMessageConnect to
1 · Motion and presence{source: "motion" | "presence", payload: true | false}Occupancy fusion’s input.
2 · Light level{source: "illuminance", payload: <lux>}The motion lighting policy’s input.

How a report is read

  • Occupancy (occupancy) is motion, or presence with Occupancy is set so; presence (presence) is presence.
  • Light level is illuminance_lux where the device sends it (older devices, beside a raw illuminance), otherwise illuminance, in lux.
  • Only changes are sent: a report whose values haven’t changed, such as a battery or temperature update, sends nothing.
  • A retained occupancy or presence, with retain set for the device in Zigbee2MQTT, is never acted on: after a restart it is an old reading, and a light switched on from it would be wrong. The next report the sensor sends is passed on, whatever it says. A retained light level is passed on.
  • Availability shows on the status (offline); nothing is sent for it.
  • After a restart the room learns the sensor’s state on its next change: Zigbee2MQTT doesn’t retain a device’s state by default, and a battery sensor can’t be asked for a reading.
