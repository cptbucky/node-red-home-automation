Motion lighting policy

Message shapes, outputs and settings for the node that turns occupancy and light level into lighting intents for a room.

On this pageLights on when occupied and dark. Off once vacant.InputsOutputsSettingsOptional MQTT and Home AssistantStatusAfter a restart
home-motion-lighting-policy1 input · 2 outputshome automation

Lights on when occupied and dark. Off once vacant.

The motion lighting policy turns normalised occupancy, illuminance and enable-state events into msg.lighting intents: ON when the room is occupied and the light level is at or below the lux cutoff (or no level has been reported yet), and OFF once it has been vacant for the vacancy time. In the palette it is motion lighting policy (home-motion-lighting-policy); on the canvas it shows its name, or “<area> motion policy”.

Wall switches go to the switch lighting policy, not here; switch messages sent to this node are ignored.

Looking for wiring?

Follow Motion and occupancy for the sensor path, and Room lighting for the room it feeds.

Inputs

Each message names its kind in msg.source.

Input messages
msg.sourceValueMeaning
occupancymsg.payload.occupiedFrom the occupancy fusion node.
illuminanceluxThe light level. Lights switch on at or below the cutoff, and also before any level has been reported.
lightmsg.payload.state, an object or JSON stringA light’s report. A state of OFF cancels a pending vacancy timer; anything else is ignored.
area-enabledtrue / falseEnables this node’s motion lighting. Any other value, such as "ON" (accepted before 6.0), is refused: nothing changes, and the node logs a warning once per deploy and shows it on its status.
global-enabledtrue / falseEnables motion lighting for every motion node. Refused values as for area-enabled.
delaysecondsA new vacancy time, in the same unit as Vacancy seconds.
illuminance-cut-offluxA new lux cutoff.
pausetrue / false, with msg.ownertrue pauses motion lighting and false releases it, for the owner in msg.owner (for example a cover’s name), which is required. A pause lasts at most the Maximum pause unless sent again.
startupNoneAnnounces its publications again.
msg.status from a Status nodeMQTT out’s “connected”Taken as the startup message (msg.source = "startup"), so the node announces itself again once the broker can take it. Wire in a Status node whose scope is your MQTT out node. Any other status message is ignored.

Motion lighting acts only while no owner holds a pause, and a pause cancels a pending vacancy timer, as switching it off does. A vacancy while paused or switched off isn’t forgotten: when motion resumes (every pause released or run out, and both enables on) in a room still vacant, the vacancy timer starts then, and the off intent’s vacantSince is when the room went vacant. A pause never changes the enables, which are the user’s own: wire a cover’s moving output here to pause motion while it moves.

A delay or illuminance-cut-off message overrides the setting, and lasts across restarts until a deploy gives the node a different Vacancy seconds or Lux cutoff, which then applies. Lasting across a redeploy or restart needs a context store.

Outputs

The port order is fixed.

Two output ports
PortMessageConnect to
1 · Lighting intentsmsg.lighting = {kind: "intent", targets, state, source}: ON for ON targets, OFF for OFF targets. The OFF intent carries vacantSince.The room lighting controller.
2 · MQTT publicationsState, availability and discovery, when publishing is on.An MQTT out node.

Because the OFF intent carries vacantSince, the room lighting controller keeps any light a person set after the room went vacant.

Optional MQTT and Home Assistant

Off unless switched on, and then named after the Area. Publications go on output 2. Wire an MQTT in node on home/<area>/motion/+/set into this node.

Published state and incoming requests
TopicDirectionPayload
home/<area>/motion/enabled/stateOutput 2 · retainedON or OFF: this node’s enable.
home/<area>/motion/delay/stateOutput 2 · retainedThe vacancy delay in seconds.
home/<area>/motion/availabilityOutput 2online or offline.
home/<area>/motion/enabled/setMQTT in → policyON or OFF, as area-enabled. Retained messages are ignored.
home/<area>/motion/delay/setMQTT in → policyA delay of 0 to 86400 seconds, as delay.

The shared global-enabled is not published, and the switch shows this node’s enable only, so motion can still be off everywhere while it shows on. The node announces itself once the flows have started, and again on msg.source = "startup". See Home Assistant.

Status

The status reads enabled while motion lighting can act; otherwise paused while any owner holds a pause, even if it is also switched off, and disabled when it is only switched off. Then come the last light level (lux ? before one is reported) and the vacancy delay, for example enabled · 4 lux · 120s. The dot is green while enabled and grey otherwise. A refused enable value shows a yellow ring, refused <source> <value>: send true or false.

After a restart

When the node starts with nothing saved (its first deploy, or a redeploy or restart without a context store), it doesn’t know whether the room is occupied, so it counts the room as vacant from then: unless occupancy is reported within Vacancy seconds, it sends its OFF intent. Someone sitting still in a lit room has the lights switched off after the delay unless motion is seen. With a context store, a running off-timer carries on instead.
