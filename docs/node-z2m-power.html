A plug’s watts, for whatever judges them

The zigbee2mqtt power node (type home-z2m-power; canvas label: its name, its friendly name, or “zigbee2mqtt power”) turns a Zigbee2MQTT plug or meter’s power into one neutral reading, msg.power. A display mode controller takes it as its projector’s power, judged with its own on and off watts, and a scene takes it for its End below. It subscribes through Node-RED’s MQTT broker node itself: no MQTT in, change or function nodes, and never Home Assistant.

The devices: Zigbee2MQTT’s supported devices (its page there names each device’s fields).

Inputs

Input messages
FromMessageEffect
The broker<base>/<friendly name>: the device’s state as JSONIts power, as below.
The broker<base>/<friendly name>/availabilityShown on the status.
A display controller’s third output, or your flowmsg.power = {kind: "read"}Asks the plug for its power: {"power": ""} on <base>/<friendly name>/get. It also asks each time the broker connects. A plug that doesn’t answer /get reports on its next change.

Output

One output port
PortMessageConnect to
1 · Power readingsmsg.power = {kind: "observed", watts, observedAt}, and msg.payload the wattsA display controller’s input (its projector’s power), or a scene’s input (its End below).

Fixed: watts only, from power as a number of 0 or more; anything else is ignored with a trace. Only a change is sent. observedAt is when the report arrived. A retained report (with retain set for the plug in Zigbee2MQTT) is an old one, so it is never passed on; the read on connect brings a fresh one.
