Wire a cover

Connect a blind, shutter or curtain through the shelly cover adapter node. Then add presets, manual control and a group without losing sight of what the motor actually did.

Before you wire it

This guide connects a calibrated relay-module cover through the shelly cover node (home-shelly-cover), an adapter that speaks the device’s own MQTT API. You need the device’s MQTT topic prefix and a broker connection in Node-RED.

  • Use a compatible generation-2-or-later relay device in cover mode, calibrated on the device first.
  • Enable MQTT and MQTT Control on the device.
  • Keep RPC status notifications enabled so changes are reported. Generic status updates can provide additional full reports.

The controller’s positions are 0 = closed and 100 = open. For a motor with no reliable position, use open, close and stop only instead; this position-adapter guide is not that device path.

Wire the command and observation loop

The adapter translates messages. The controller decides whether a move is complete. Keep both directions connected.

Two wires
FromConnect toWhy
Controller output 1shelly cover inputPass neutral device commands unchanged.
shelly cover output 2Controller inputFeed back observations, availability and command results.
  1. Set the adapter’s topic prefix and Broker.

    Use the prefix configured on your device. Set Cover ID to 0, or 1 for a device’s second cover. With a Broker, the adapter subscribes to <prefix>/# and publishes the commands itself. An adapter saved before 6.2 keeps its MQTT in node on <prefix>/# and its first output to MQTT out until you choose one.

  2. Choose a position cover.

    On the controller, leave Cover as “Takes a position (0 to 100)”. Set Invert positions only if the device reports 0 as open.

  3. Nothing to send at startup.

    The adapter reads the cover each time the broker connects, and the controller re-reads a move that was in progress, so neither trusts old state. A controller that publishes runs its startup on each connect too.

  4. Watch state and results.

    Connect controller output 2 to a Debug node. Output 3 reports whether it is moving; output 4 is for optional MQTT publications, not device commands.

A position echo is not a stopped motor.

A move confirms from a stopped report at the target, or a position that stays the same for the settle time. Set Settle time to at least the interval between motor travel reports.

Request a position or preset

Use an Inject node or another policy to send a number, "open", "close", "stop", or a named preset to the controller.

Inject → cover controller · request a position
msg.payload = 60;
return msg;

The default Presets setting is {"partial":60}. To use it:

Inject → cover controller · use a named preset
msg.payload = "partial";
return msg;

A still cover already at its target is confirmed without sending another move.

Leave a person’s move alone

Mark requests from schedules or automatic policies with respectManual. They wait while the cover is held by a person’s move.

Automatic request
msg.payload = "partial";
msg.respectManual = true;
return msg;

A new request without that flag takes control back. For a wall button that should stop a moving cover, set stopIfMoving:

Button request · stop if moving, otherwise open
msg.payload = "open";
msg.stopIfMoving = true;
return msg;
Pause motion lighting, not the user’s enable switch.

Controller output 3 can feed the motion policy’s pause input: set msg.source = "pause" and a distinct msg.owner. Keep the boolean payload. Never use the area-enabled input for this.

Move several covers as one

Add a cover group. Its default members are ["left","right"]. Output 1 is the group result; each following output is a request for the labelled member.

  1. Connect the group’s left and right outputs to their respective cover controllers.
  2. Connect each controller’s output 2 back to the group input.
  3. Send the request to the group. It assigns each member its own request identity.

The group reports ready only when every member confirms. If some fail, it reports partial or none-confirmed with individual member details. A silent member becomes no-answer at the answer deadline (default 120 seconds).

Each member keeps its own device connection. A group has no Home Assistant entity; Home Assistant can group the individual cover entities itself.

The Cover pair example flow (Import → Examples) wires a group to the left and right curtains of a pair, with inject nodes standing in for their reports.

Check the result

Read the outcome
What you seeWhat it means
Moving, then readyFresh reports confirm the cover has stopped at its target.
not-calibrated / position-unknownThe device cannot provide a usable position. Calibrate it or restore its position knowledge; do not invent a reading.
unavailableThe device is offline. No device command is sent; it is read again when it returns.

For output messages, optional Home Assistant discovery and timing defaults, open the cover controller reference.
