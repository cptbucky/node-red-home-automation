Lighting nodes

Switch lighting policy

Message shapes, output and settings for the node that turns wall switch edges or button actions into lighting intents. It tracks whether the switch input is fresh, stale or unavailable.

On this pageA press becomes an intent.InputsOutputsSettingsStatus
home-switch-lighting-policy1 input · 1 outputhome automation

A press becomes an intent.

Turns raw switch edges, or single and double actions already classified by the device, into msg.lighting intents for the room lighting controller. It keeps no occupancy or motion state. In the palette it is home-switch-lighting-policy; on the canvas it shows its name, or “<area> switch policy”, or “switch policy”.

A single press toggles the targets. A double press switches them on at full brightness as a person’s manual setting.

Looking for wiring?

Follow Wire wall switches for the switch connections and the room controller after it.

Inputs

Each message names its kind in msg.source. Other sources are ignored.

Input messages
msg.sourceOther propertiesEffect
"switch"msg.payload = {state: true | false}; optional msg.retain, msg.baseline, msg.observedAt or msg.payload.observedAtA raw wall switch state. A change is an edge; a second edge within Raw-edge window ms is a double press, otherwise the first edge becomes a single press when the window ends.
"switch-action"msg.payload = "single" or "double", or {action: …}A press the device already classified. Other actions (such as long) and retained messages are ignored.
"switch-availability"msg.payload = online, available, on or true; offline, unavailable, off or falseOffline forgets the baseline; the first observation after it re-baselines without a press.

A retained observation, or one marked msg.baseline = true (for a polled snapshot), only sets the baseline and never becomes a press. A repeated, unchanged state refreshes freshness without a press. With no baseline yet, the first non-retained report counts as a change and becomes a press: it sends a TOGGLE. Mark the first read of a switch with msg.baseline = true to avoid that. After an offline availability message, the first report re-baselines without a press.

The baseline is kept in the node’s context, so it survives a restart only with a context store configured (see the README’s Recommended setup). A kept baseline counts as unconfirmed until this runtime receives an observation.

Outputs

One output: lighting intents, for the room lighting controller’s input.

Single press · msg.lighting
{
  kind: "intent",
  targets: ["main"],
  state: "TOGGLE",
  source: "wall",
  person: true
}

A double press sends state: "ON" with manual: true and values: {brightnessPct: 100}. Every intent carries person: true.

Settings

Defaults below are from the editor definition. Note the units: the window is in milliseconds, freshness in seconds.

Editor settings and exact defaults
Setting / propertyDefaultMeaning
Namename · stringEmptyDisplay label.
Areaarea · stringEmptyOptional; labels the node and its traces.
Targetstargets · JSON array["main"]The room controller targets the intents name. A non-empty JSON array of strings.
Raw-edge window msswitchWindowMs · number500How long after one edge a second edge counts as a double press. Zero or more.
Input freshness secondsswitchFreshnessSeconds · number3600How long after the last observation the switch input counts as fresh. Greater than zero.

Status

Node status
StatusMeaning
switch fresh · <age> (green)Observed in this runtime within the freshness time.
switch stale · <age> (yellow)The baseline is known but older than the freshness time, unconfirmed since start, or without a timestamp.
switch unavailable (red)The last availability message said offline.
awaiting switch baseline (yellow)No switch state is known yet.

The age shows in seconds, minutes or hours, and is refreshed on a timer as the input ages.
