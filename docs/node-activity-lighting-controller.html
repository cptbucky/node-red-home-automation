Activity lighting controller

Message shapes, output ports and settings for the node that styles room lights for a theatre activity. It only touches lights that are already on and not set by a person.

On this pageAtmosphere without taking over.InputsOutputsSettingsProfilesHow lights are judged and releasedStatus
home-activity-lighting-controller1 input · 2 outputshome automation

Atmosphere without taking over.

Applies a configured style, such as dim and warm for a film, to room lights that are already on and not manually owned, and holds them in the room lighting controller while the activity runs. It never switches a light on and never talks to a light itself: it sends standard msg.lighting intents to a room lighting controller. Room-light failure only degrades an activity; it never makes one succeed or fail.

In the palette it is activity lighting controller under home automation; on the canvas it shows its name, or activity lighting when unnamed.

Looking for wiring?

Follow Home theatre, where the theatre activity controller sends this node its lighting commands.

Inputs

Every input is msg.activityLighting with a kind.

msg.activityLighting kinds
kindOther fieldsUse
intentrequestId, generation, profile, optional requestedAtApply a configured profile; generation is a positive integer.
observedgeneration, target, on, observedAt, optional manual, available, valuesOne light’s state. Lights outside the profile and readings older than the request are ignored. available: false fails the profile (lighting-unavailable).
command_resultgeneration, ok, optional reasonResult of an apply. ok: true is not confirmation.
refreshoptional requestId, generation, profileFrom the theatre activity controller: re-read the lights, or adopt the activity’s profile after a start with nothing saved.
startupNoneRe-read the lights for the profile in hand, with a deadline.
tickgenerationSent by the node itself at the confirmation deadline.

The theatre activity controller’s lighting command (moved from msg.theatreCommand) carries profile from the activity’s lighting values, so it already has the intent shape. Its light readings come from the room lighting controller’s third output, which passes on each light’s reading (from the light’s adapter) with whether a person set it; wire that output here, as the Home theatre activity example does. A flow can also send observed events itself, one per light, with the generation of the request they answer, fields and showsLast.

Outputs

The port order is fixed.

Two output ports
PortMessageConnect to
1 · Room-lighting commandsmsg.activityLightingCommand = {operation, requestId, generation, profile, attempt}, operation apply, observe or release. An apply or release also carries msg.lighting.The room lighting controller’s input.
2 · Theatre target statemsg.theatre = {kind: "target_state", target: "lighting", requestId, generation, status, observedAt, details}, with classification and failure when set.The theatre activity controller’s input.

details holds the profile, how many lights matched, how many were preserved (off, or a person’s before the request, so left alone), how many were expected, and metrics.

  state: "ON",
  values: {brightnessPct: 25, colorTempKelvin: 2500},
  source: "activity",
  owner: "activity",
  updateOnOnly: true,

}

Profiles

Profile and light names are lowercase, starting with a letter. targets lists the room’s light names, without duplicates; values is in the package’s own units.

Profiles JSON · from the example flow
{
  "off": {"targets": [], "values": {}},
  "tv":  {"targets": ["main"], "values": {"brightnessPct": 25, "colorTempKelvin": 2500}}
}
  • brightnessPct runs from 0 (the dimmest the light goes, not off) to 100.
  • colorTempKelvin must be above 0.
  • Zigbee2MQTT’s own brightness and color_temp were removed in 6.0: a profile using them is an invalid configuration.
  • A profile with no targets, such as off, is ready at once.

How lights are judged and released

Each light is judged by what it reports, through its adapter. A light that is off, or a person’s before this request, is preserved, not styled. A light this request held that a person then changes (the room makes it manual) is a manual override: the node reports manual_override, as the display, receiver and backlight do, and as lighting is optional the theatre is degraded, not failed. The next request takes that light back. A light that has reported none of the profile’s fields since the node started, such as one that only switches on and off, is confirmed by being on; the node warns once per deploy that the values may not apply. Mark such a light onOffOnly on the room so the room won’t send them. Once a light has reported one of the fields, it is held to the profile’s values.

A failed command_result or a confirmation timeout re-applies until Attempts, then fails with the reason, command-failed or confirmation-timeout.

A light with no reading at all by the confirmation timeout, such as a Zigbee2MQTT group whose state Zigbee2MQTT doesn’t retain after a restart, is unobserved: it isn’t re-applied and fails nothing. The profile is ready without it, the node’s status counts it (tv: ready · 1 unobserved), and its report to the theatre carries details.unobserved, so the theatre shows lighting as degraded with reason unobserved while the activity stays ready. The light’s first reading clears it and is judged like any other. The timeout runs after a restart and after a refresh too, so the profile never waits on such a light indefinitely.

When a new profile no longer includes a light, including a switch to an off profile with no targets, it sends msg.lighting = {kind: "release", owner, targets, source: "activity"} for those lights, and the room controller gives each back what it was before the activity took it: one the room was running is restyled, one a person had set gets their values back (see owners stack). When the lights it last held are unknown (state saved by an older version, whose profile is no longer configured), the release has no targets: {kind: "release", owner, source: "activity"} releases every light held under its owner.
