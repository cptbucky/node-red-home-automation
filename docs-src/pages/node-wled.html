Backlight power through WLED’s own MQTT

The wled node (type home-wled; canvas label: its name, its device topic, or “wled”) turns a backlighting controller’s set_power into WLED’s ON or OFF, and WLED’s brightness reports into the controller’s readings. It talks to WLED through Node-RED’s MQTT broker node, with no MQTT in or out nodes, no function nodes, and never Home Assistant.

The device: WLED (the WLED project’s documentation).

Inputs

Input messages
FromMessageEffect
Backlighting controller, output 1msg.backlightingCommand = {operation: "set_power", generation, power}Publishes ON or OFF on the device topic and answers command_result ok; while WLED is offline, publishes nothing and answers not ok, reason unavailable.
Backlighting controller, output 1msg.backlightingCommand = {operation: "observe", generation}Answers with the last power WLED reported, while it is online. With no report since Node-RED started, it answers when WLED next reports.
The broker<device topic>/g, <device topic>/statusIts readings and availability (see below). An MQTT in node wired to its input changes nothing.

How WLED is read

  • Power comes from the brightness WLED publishes on <device topic>/g after every change: 0 is off, anything else on.
  • Whose change isn’t said: WLED reports a change from its own app, a button or another system the same as one from this node. The backlighting controller judges a reading against what it wants, so a change it didn’t make is a manual change.
  • Availability is online or offline on <device topic>/status. WLED’s documentation doesn’t describe this topic. On the firmware we tested, the broker holds a retained online for it, and WLED publishes online again, not retained, with each change. Until it reports, a command is sent; only offline refuses one.
  • After a restart there is no reading until WLED next changes. On the firmware we tested, each change publishes /g, /c, /v and /status, none of them retained, and nothing reads its state on demand over MQTT: {"v":true}, or an {"on":true} that changes nothing, on <device topic>/api publishes nothing. So after a start with nothing saved, the theatre’s recovery gets no backlighting answer until then.
